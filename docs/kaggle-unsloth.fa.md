# اجرای آنسلاث روی ردهٔ رایگان دو-کارتی Kaggle

**زبان:** [English](kaggle-unsloth.md) · فارسی · [Deutsch](kaggle-unsloth.de.md)

---

این نوشته همراه عملی [آنسلاث و لورا](unsloth-lora.fa.md) است. آن صفحه توضیح می‌دهد *چرا*
این روش در ۱۶ گیگابایت جا می‌شود؛ این صفحه توضیح می‌دهد *چگونه واقعاً اجرایش کنیم*:
راه‌اندازی، سامانهٔ فایل، نصب، به‌کارگیری هر دو کارت، خودکارسازی از خط فرمان، و اینکه دقیقاً
چه چیزهایی خراب شد.

همهٔ آنچه اینجا آمده روی ردهٔ رایگان انجام شده است. در این پروژه هیچ رایانش پولی به کار
نرفته است.

---

## ردهٔ رایگان واقعاً چه می‌دهد

| منبع | سهمیه |
|---|---|
| کارت گرافیک | **دو NVIDIA Tesla T4**، هر کدام ۱۶ گیگابایت |
| سهمیهٔ GPU | **۳۰ ساعت در هفته**، بازنشانی هفتگی |
| بیشینهٔ زمان هر نشست | ۹ ساعت (GPU)، ۱۲ ساعت (CPU/TPU) |
| سهمیهٔ TPU | ۲۰ ساعت در هفته |
| فضای خروجی (`/kaggle/working`) | ۲۰ گیگابایت، به‌عنوان خروجی دفترچه نگهداری می‌شود |
| دسترسی اینترنت | در دسترس، اما نیازمند **حساب تأییدشده با تلفن** |

تمام این پروژه (سه اجرای آموزش، یک مقایسهٔ کدگشایی و یک دفترچهٔ ارزیابی) **کمتر از سه
ساعت** از این بودجهٔ ۳۰ ساعته را مصرف کرد.

دو محدودیت از بقیه مهم‌ترند:

**اینترنت نیازمند تأیید تلفنی است.** بدون آن، `pip install unsloth` شکست می‌خورد و مدل از
هاگینگ‌فیس دانلود نمی‌شود. این رایج‌ترین دلیلی است که دفترچه‌ای که «باید کار کند» کار
نمی‌کند.

**کارت T4 از نسل Turing است: بدون bfloat16.** همه‌چیز در fp16 اجرا می‌شود. این جزئیات
بی‌اهمیت نیست: خانواده‌های کاملی از مدل‌ها را کنار می‌گذارد که در fp16 مستعد زیان NaN‌اند،
و همین دلیل انتخاب Qwen3 به‌جای Gemma در این پروژه بود.

## راه‌اندازی یک دفترچه

در تابلوی سمت راست ویرایشگر Kaggle:

۱. **Session options → Accelerator → GPU T4 x2.** نه «GPU P100» که تک‌کارتی است.
۲. **Session options → Internet → On.**
۳. **Add Input → Datasets** → دادهٔ آموزشی را پیوست کنید.

سپس *Run All*. همهٔ تنظیمات قابل‌تغییر این پروژه در یک سلول در بالای دفترچه‌اند.

### سامانهٔ فایل

| مسیر | کاربرد |
|---|---|
| `/kaggle/input/<dataset-slug>/` | مجموعه‌داده‌های پیوست‌شده، **فقط‌خواندنی** |
| `/kaggle/working/` | خروجی شما، هنگام ذخیرهٔ دفترچه **نگهداری می‌شود** |
| `/kaggle/temp/` | فضای موقت، در پایان نشست دور ریخته می‌شود |

مجموعه‌داده‌ها در عمقی غیرقابل‌پیش‌بینی سوار می‌شوند، پس این پروژه هرگز مسیر را ثابت
نمی‌نویسد و به‌جای آن دنبال نام فایلی شناخته‌شده می‌گردد:

<div dir="ltr">

```python
def find_data_dir(root):
    """Kaggle مجموعه‌داده‌ها را در عمق نامعلوم سوار می‌کند؛ پوشه را با فایلی شناخته‌شده بیاب."""
    matches = sorted(Path(root).rglob("all_train.jsonl"))
    if not matches:
        raise FileNotFoundError(f"فایل all_train.jsonl زیر {root} نیست؛ مجموعه‌داده پیوست شده؟")
    return matches[0].parent
```

</div>

این عادت بارها به کار آمد، به [دام‌ها](#دام‌هایی-که-وقت-واقعی-گرفتند) نگاه کنید.

## نصب آنسلاث روی Kaggle

ایمیج‌های Kaggle نسخه‌های خودشان از PyTorch و Transformers را دارند که اغلب با نیاز
Unsloth ناسازگارند. پس نصب‌ها **قفل‌شده و برای هر خانوادهٔ مدل متفاوت‌اند**:

<div dir="ltr">

```python
if MODEL_PRESET == "gemma-4-e4b":
    !pip install -q unsloth
    !pip install -q --no-deps transformers==5.10.1 "tokenizers>=0.22.0,<=0.23.0"
    !pip install -q "huggingface_hub>=1.5.0,<2.0"
    !pip install -q torchcodec
    !pip install -q --no-deps --upgrade timm
else:                                    # qwen3-4b
    !pip install -q pip3-autoremove
    !pip install -q torch torchvision torchaudio xformers --index-url https://download.pytorch.org/whl/cu128
    !pip install -q unsloth
    !pip install -q --no-deps --upgrade "torchao>=0.16.0"
    !pip install -q transformers==4.56.2
    !pip install -q --no-deps trl==0.22.2
```

</div>

سه نکته که باید فهمید:

**این نسخه‌های قفل‌شده از دفترچه‌های رسمی خود Unsloth در Kaggle آمده‌اند**، نه از حدس. هر
خانوادهٔ مدل ترکیبی دارد که روی این ایمیج اثباتاً کار می‌کند؛ انحراف از آن خطای import یا
تعارض خاموش نسخه‌ها می‌سازد.

**گزینهٔ `--no-deps` عمدی است.** بسته را نصب می‌کند بدون آنکه pip «از سر لطف» بسته‌های
همسایه را دوباره حل و نسخه‌شان را پایین بیاورد. بدون آن، نصب `trl` می‌تواند `transformers`
را به نسخه‌ای دیگر بکشد و وصله‌های Unsloth را بشکند.

**مدل‌های Gemma و Qwen3 به پشته‌های ناسازگار نیاز دارند**: `transformers 5.10.1` در برابر
`4.56.2`. این دو کنار هم نمی‌نشینند؛ به همین دلیل کلید انتخاب مدل، سلول نصب را هم عوض
می‌کند. همین به‌تنهایی دلیل خوبی است که در هر دفترچه یک خانوادهٔ مدل انتخاب کنید.

نصب حدود ۵ دقیقه طول می‌کشد و باید یک بار در هر نشست اجرا شود.

### راستی‌آزمایی محیط

کتابخانهٔ Unsloth هنگام import یک بنر چاپ می‌کند. آن را بخوانید: آنچه واقعاً رخ داده را
تأیید می‌کند:

<div dir="ltr">

```
==((====))==  Unsloth 2026.9.4: Fast Qwen3 patching. Transformers: 4.56.2.
   \\   /|    Tesla T4. Num GPUs = 2. Max memory: 14.562 GB. Platform: Linux.
O^O/ \_/ \    Torch: 2.10.0+cu128. CUDA: 7.5. CUDA Toolkit: 12.8. Triton: 3.6.0
\        /    Bfloat16 = FALSE. FA [Xformers = 0.0.35. FA2 = False]
```

</div>

عبارت `Num GPUs = 2` تأیید می‌کند تنظیم شتاب‌دهنده اثر کرده است. عبارت
`Bfloat16 = FALSE` محدودیت T4 را تأیید می‌کند. عبارت `Fast Qwen3 patching` تأیید می‌کند
Unsloth معماری را شناخته است. اگر هر یک از این‌ها نادرست بود، همان‌جا بایستید و بعداً
آموزش را عیب‌یابی نکنید.

## به‌کارگیری هر دو کارت

دو راه برای خرج‌کردن کارت دوم هست و پیش‌فرض اینجا کمتر بدیهی است.

### پیش‌فرض: دو کار متفاوت به‌موازات

آموزش یک مدل ۴ میلیاردی با QLoRA روی **یک** T4 جا می‌شود. تقسیم یک کار میان دو کارت در این
مقیاس سود کمی دارد و ریسک هماهنگی می‌افزاید. به‌جای آن، کارت ۰ آموزش می‌دهد و کارت ۱
پاسخ‌های پایه را از مدل آموزش‌ندیده تولید می‌کند، پاسخ‌هایی که به‌هرحال برای اثبات اثر
آموزش لازم دارید.

سازوکار، زیرفرایندهای ساده با کارت تثبیت‌شده است:

<div dir="ltr">

```python
def run(cmd, gpus, name, background=False):
    """اسکریپت را روی کارت‌های داده‌شده و در پوشهٔ خودش اجرا کن."""
    cwd = f"{WORK}/run_{name}"
    os.makedirs(cwd, exist_ok=True)
    env = {**os.environ, "CUDA_VISIBLE_DEVICES": gpus, "PYTHONPATH": SCRIPTS}
    if background:
        log = open(f"{cwd}/log.txt", "w")
        return subprocess.Popen(cmd, env=env, cwd=cwd, stdout=log, stderr=subprocess.STDOUT)
    ...
```

```python
baseline = run(baseline_cmd, "1", "baseline", background=True)   # کارت ۱
run([PY, *train_args], "0", "train")                             # کارت ۰
code = baseline.wait()
```

</div>

دو نکتهٔ آسان‌ازدست‌رفتنی:

**هر فرایند پوشهٔ کاری خودش را می‌گیرد.** کتابخانهٔ Unsloth حافظهٔ نهان کرنل‌های کامپایل‌شده
را در پوشهٔ جاری می‌نویسد. دو فرایند با پوشهٔ کاری مشترک بر سر این حافظه رقابت می‌کنند. این
نظری نیست: دقیقاً به همین دلیل `cwd=f"{WORK}/run_{name}"` وجود دارد.

**متغیر `CUDA_VISIBLE_DEVICES` برای هر زیرفرایند تنظیم می‌شود، نه سراسری.** هر فرایند دقیقاً
یک کارت می‌بیند و آن را `cuda:0` می‌نامد. هیچ بخشی از اسکریپت آموزش اصلاً از GPU خبر ندارد.

### اختیاری: آموزش توزیع‌شدهٔ واقعی

<div dir="ltr">

```python
run([PY, "-m", "torch.distributed.run", "--nproc_per_node=2", *train_args], "0,1", "train")
```

</div>

این کار می‌کند و در این پروژه برای آموزش کامل SmolLM2 به کار رفت. همچنین بدترین شکست پروژه
را ساخت.

## شکستی که باید برایش برنامه داشت

اجرای SmolLM2 **هر ۵۱ گام آموزش را روی هر دو T4 با موفقیت** کامل کرد و سپس از کار افتاد:

<div dir="ltr">

```
NCCL ALLGATHER sequence number mismatch
```

</div>

*پس از* آموزش مرد، هنگام بارگذاری بهترین نقطهٔ ذخیره برای خروجی‌گرفتن. آموزش سالم بود؛
هماهنگی جمعی در مسیر خروجی نه.

آنچه اجرا را نجات داد این بود که **Kaggle پوشهٔ `/kaggle/working` را حتی وقتی دفترچه شکست
می‌خورد به‌عنوان خروجی نگه می‌دارد.** هر ۴۱ فایل خروجی از جمله نقاط ذخیره سالم ماندند.
راه‌حل، دفترچه‌ای جداگانه و تک‌فرایندی بود که نقطهٔ ذخیرهٔ حفظ‌شده را بارگذاری، ارزیابی و
خروجی گرفت، بدون هیچ عملیات جمعی. در ۲۱۸ ثانیه اجرا شد.

**سه قاعده از این برمی‌آید:**

۱. **خروجی‌گرفتن نباید در همان فرایند آموزش توزیع‌شده باشد.** آموزش بده، نقطهٔ ذخیره بنویس،
   خارج شو. خروجی را جدا بگیر.
۲. **در هر دوره نقطهٔ ذخیره بنویس.** همین است که نجات را ممکن می‌کند.
۳. **دفترچهٔ شکست‌خوردهٔ Kaggle یعنی اجرای ازدست‌رفته نیست.** پیش از اجرای دوباره، خروجی را
   ببینید: بخش گران‌قیمت شاید همین حالا روی دیسک باشد.

## خودکارسازی از خط فرمان

برای یک اجرا، رابط وب کافی است. برای مجموعه‌ای از آزمایش‌ها، API کاگل به‌مراتب بهتر است، و
اجازه می‌دهد بدون مرورگر همه‌چیز را پیش ببرید.

<div dir="ltr">

```bash
pip install kaggle
# توکن از kaggle.com/settings -> API -> Create New Token
# در ~/.kaggle/access_token ذخیره می‌شود
```

</div>

### بارگذاری مجموعه‌داده

<div dir="ltr">

```bash
# فایل dataset-metadata.json کنار فایل‌های داده:
# { "title": "Shahnameh Style SFT",
#   "id": "<username>/shahnameh-style-sft",
#   "licenses": [{"name": "CC0-1.0"}] }

kaggle datasets create -p .        # به‌طور پیش‌فرض خصوصی
```

</div>

### فرستادن و اجرای دفترچه

فایل `kernel-metadata.json` هر چیزی را که تابلوی سمت راست انجام می‌داد کنترل می‌کند:

<div dir="ltr">

```json
{
  "id": "<username>/shahnameh-qwen3-4b-unsloth",
  "title": "Shahnameh Qwen3-4B Unsloth",
  "code_file": "shahnameh-qwen3-4b-unsloth.ipynb",
  "language": "python",
  "kernel_type": "notebook",
  "is_private": true,
  "enable_gpu": true,
  "enable_internet": true,
  "dataset_sources": ["<username>/shahnameh-style-sft"],
  "kernel_sources": [],
  "machine_shape": "NvidiaTeslaT4"
}
```

</div>

**همین `"machine_shape": "NvidiaTeslaT4"` است که دو کارت T4 را انتخاب می‌کند.** تنها
`enable_gpu: true` ممکن است یک کارت بدهد. این فیلد مستندسازی ضعیفی دارد؛ راه مطمئن برای
یافتن مقدار درست، گرفتن فراداده از دفترچه‌ای است که از پیش درست تنظیم شده:

<div dir="ltr">

```bash
kaggle kernels pull <username>/<existing-notebook> -m -p .
```

</div>

سپس:

<div dir="ltr">

```bash
kaggle kernels push -p .                       # فرستادن، اجرا را هم آغاز می‌کند
kaggle kernels status <username>/<notebook>    # PENDING / RUNNING / COMPLETE / ERROR
kaggle kernels output <username>/<notebook> -p ./out
```

</div>

یک حلقهٔ ساده معمولاً کافی است:

<div dir="ltr">

```bash
while true; do
  S=$(kaggle kernels status <username>/<notebook> | grep -o 'KernelWorkerStatus\.[A-Z_]*')
  echo "$(date +%H:%M:%S) $S"
  case "$S" in *COMPLETE*|*ERROR*) break;; esac
  sleep 120
done
```

</div>

### زنجیره‌کردن دفترچه‌ها

خروجی یک دفترچه می‌تواند ورودی دفترچهٔ دیگر باشد، از راه `kernel_sources`. این پروژه از
همین برای اجرای مقایسهٔ کدگشایی روی آداپتور از پیش آموزش‌دیده و بدون آموزش دوباره استفاده
کرد:

<div dir="ltr">

```json
"kernel_sources": ["<username>/shahnameh-qwen3-4b-fa-only"]
```

</div>

## دام‌هایی که وقت واقعی گرفتند

همهٔ این‌ها در این پروژه رخ داد. هیچ‌کدام در مستندات رسمی نیست.

**خروجی دفترچه در مسیری بلندتر از انتظار سوار می‌شود.** دفترچه‌ای که با `kernel_sources`
پیوست شده *در* `/kaggle/input/<slug>/` ظاهر نمی‌شود. مسیر واقعی این است:

<div dir="ltr">

```
/kaggle/input/notebooks/<username>/<slug>/...
```

</div>

ثابت‌نوشتن مسیر کوتاه خطای `Can't find 'adapter_config.json'` و شکست اجرا در حدود ثانیهٔ
۱۶۰ می‌سازد. به‌جای فرض‌کردن، جست‌وجو کنید:

<div dir="ltr">

```python
found = [os.path.dirname(p)
         for p in glob.glob("/kaggle/input/**/adapter_config.json", recursive=True)
         if "checkpoint" not in p]
```

</div>

**ابزار خط فرمان Kaggle مسیرهای مطلق ویندوز را خراب می‌کند.** فرمان
`kaggle datasets create -p "C:/long/path"` مسیر موقتی نادرست می‌سازد و با
`[Errno 2] No such file or directory` شکست می‌خورد. راه دور زدن: از داخل همان پوشه با
`-p .` اجرا کنید.

**دفترچه‌های دارای نویسهٔ غیر-ASCII از ویندوز بارگذاری نمی‌شوند.** فرستادن دفترچه‌ای با متن
فارسی خطای `'charmap' codec can't decode byte 0x81` می‌دهد. UTF-8 را اجباری کنید:

<div dir="ltr">

```bash
PYTHONUTF8=1 kaggle kernels push -p .
```

</div>

**تنظیم `enable_gpu: true` به‌معنای دو کارت نیست.** بدون `machine_shape`، دفترچهٔ دوکارتی
ممکن است خاموشانه یک کارت بگیرد و هر کدی که `CUDA_VISIBLE_DEVICES=1` را تثبیت کند شکست
بخورد.

**صفحهٔ ذخیره‌شدهٔ دفترچه فقط‌خواندنی است.** برای تعامل با دفترچه (نوشتن پرسش در کادر،
اجرای یک سلول)، باید روی **Edit** بزنید تا نشست زنده آغاز شود. دیدن نسخهٔ ذخیره‌شده و انتظار
تعامل داشتن، اشتباهی رایج است.

**نشست‌های تعاملی منقضی می‌شوند.** سلول‌های نصب و بارگذاری مدل پس از پایان نشست باید دوباره
اجرا شوند. حدود ۷ دقیقه تا نخستین خروجی مفید در نظر بگیرید.
